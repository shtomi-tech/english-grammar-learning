# 修正計画｜不定詞各論図解の教材精度とモバイル整列

作成: 2026-08-22 / 対象: `english-grammar-learning`

状態: **実装・検証済み（2026-08-22）**

関連文書: [実装計画_不定詞各論の図解教材化.md](./実装計画_不定詞各論の図解教材化.md)、[DESIGN.md](../DESIGN.md)

---

## 1. 目的

不定詞14単元へ追加した各論図解について、最新実装の評価で確認した次の2点を修正する。

1. 形容詞的用法の図解例で、先行する名詞と不定詞の意味関係を一意にする。
2. 320px幅の対比カードで、内容量による高さの差を既定の範囲へ収め、同じ分類軸のカードとして読みやすくする。

修正は図解の教材表現・関連スタイル・直接対応するテストに限定する。既存の詳説、問題、採点、学習進捗には触れない。

---

## 2. 評価結果と修正方針

### 2-1. 形容詞的用法の例が文脈なしでは曖昧

対象: `content.js` の `infinitive-adjective-use`

現在の図解には次の例がある。

```html
<span class="lessonVisualCardLabel">動作主</span>
<strong><code>someone</code> ← <code>to help</code></strong>
<span>手伝う人</span>
```

`someone to help` は文脈によって、`someone`が手伝う側か、手伝われる側かを初学者が判断しにくい。図解は後半の詳説より語数が少ないため、具体例そのものが意図した関係を一意に示す必要がある。

#### 採用する修正

```html
<span class="lessonVisualCardLabel">動作主</span>
<strong><code>someone</code> ← <code>to help me</code></strong>
<span>手伝うのは someone</span>
```

- `me`を補い、`someone`が`help`の動作主であることを明示する。
- ラベル、英文、補助説明の3箇所を同じ関係にそろえる。
- 一般式の`名詞 ← to do`、対象の`something to eat`、前置詞が残る`a chair to sit on`は変更しない。
- 後半の既存詳説・例文は変更しない。

#### 採用しない案

- **`someone to help`のまま補助説明だけを増やす**: 図解上の英文自体に曖昧さが残る。
- **動作主カードを削除する**: 名詞が不定詞の動作主にも対象にもなり得るという、形容詞的用法の重要な対比が弱くなる。

### 2-2. 320pxで対比カードの高さ差が計画値を超える

対象: `styles.css` の640px以下用`.lessonVisualCards`、`tests/infinitives.spec.mjs`

評価時の実測値:

| 単元 | 320pxでのカード高の差 | 既定値 |
| --- | ---: | ---: |
| 副詞的用法（結果） | 42px | 原則36px以内 |
| 人の性質を表す形容詞と不定詞 | 41px | 原則36px以内 |

横スクロール、内容欠落、コンソールエラーは発生していないため、緊急性のある表示崩れではない。ただし、同じ対比に属するカードの視覚的な重さがそろわず、既存の実装計画とも一致していない。

#### 採用する修正

640px以下では、縦積みにした図解カードの行高を、その図解内で最も高いカードへ内容依存でそろえる。

実装候補:

```css
@media (max-width: 640px) {
  .lessonVisualCards,
  .lessonVisualScale {
    grid-auto-rows: 1fr;
  }
}
```

- 固定の`height`や`min-height`は指定しない。
- 内容が増えた場合は最大内容に追従させ、切り詰めや`line-clamp`を使わない。
- 対比型だけでなく、同じモバイルカード構造を使う図解へ一貫した規則として適用する。
- 実装後に320pxの図解全体高を再計測し、単純型650px未満・複雑型720px未満を維持できない場合は、適用セレクタを`.lessonVisualCards--contrast`へ狭める。

#### 採用しない案

- **カード本文を短縮する**: 教材上必要な違いを表示都合で削ることになる。
- **固定高を与える**: 翻訳・英文の折り返しや将来の文言変更に弱い。
- **短いカードを上寄せしたまま許容値だけ緩める**: 実装計画の視覚基準を実装へ合わせて後退させるだけになる。

## 4. 実装手順

### Phase 0 — 基準値と差分を固定する

1. 作業前に`git status -sb`を確認し、既存の未コミット変更を保持する。
2. 不定詞14単元の`lesson.version`と`structureVersion`を記録する。
3. 320pxで14単元の図解高、カード高、横幅を再計測する。
4. 今回の対象外ファイルをステージ・編集しない。

### Phase 1 — 教材例を明確化する

1. `infinitive-adjective-use`の動作主カードだけを修正する。
2. `someone`が`help`の動作主であることを、英文と日本語の両方で確認する。
3. 図解の必須4スロット、図解型、`aria-labelledby`を維持する。
4. 後半詳説と3問に差分がないことを確認する。

### Phase 2 — モバイルカードを整列する

1. 640px以下のグリッドへ内容依存の均等行を追加する。
2. 320 / 375 / 640 / 1280pxで14単元を再計測する。
3. カード高の差、図解全体高、ページ横幅を確認する。
4. 全体高が受入上限を超える場合だけ、対象を対比型へ狭める。

### Phase 3 — 回帰テストを追加する

`tests/infinitives.spec.mjs`へ次を追加する。

1. 形容詞的用法の図解が`to help me`と「手伝うのは someone」を含む。
2. 320pxで各図解内のカード高を配列として取得する。
3. カードが2件以上ある図解では、`max - min <= 36`を検証する。
4. 既存の図解高、横スクロール、後半本文表示の検証を維持する。

カードの対象セレクタ:

```js
.lessonVisualCard,
.lessonVisualSlot,
.lessonVisualFlowNode,
.lessonVisualTimePoint
```

関係図や時間軸で役割の異なるノードを無理に均等化しないため、高さ差の受入条件は`.lessonVisualCards`と`.lessonVisualScale`内の並列カードへ限定する。全図解要素を一括して比較しない。

### Phase 4 — 正本と公開準備を確認する

1. 元の実装計画の状態を、実装・検証結果に合わせて更新する。
2. コミット対象を`content.js`、`styles.css`、`tests/infinitives.spec.mjs`、必要な計画文書に限定する。
3. デプロイは別途ユーザーから指示された場合だけ行う。
