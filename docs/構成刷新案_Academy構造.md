## 2. Academy の構造で「効いている」もの

構造として本アプリに移植価値があるのは次の5点。装飾ではなく**情報の置き方**である。

1. **3階層が明確に分かれている**（カタログ → コース詳細 → レッスン）。現在地はパンくずで常に1行に出る。
2. **カードの語彙が全階層で統一**。`種別バッジ · 分量（n レッスン・n クイズ） · 所要時間`。この3点セットが一覧・詳細・レッスンで同じ語彙のまま繰り返される。
3. **コース詳細が「開始前の意思決定ページ」として独立している**。学習内容（終えると何ができるか）・前提条件・対象者・章構成が、レッスンを1つも開かずに読める。
4. **レッスン画面が3ペイン**。左＝コースアウトライン（章でグループ化）、中＝本文、右＝ページ内目次。前後レッスンの明示リンクと「レッスン 6／12」が本文末にある。
5. **コースの終端が固定形**。全レッスン → コースクイズ → 修了バッジ。学習単位と認定単位が最初から分かれている。

一方、**そのまま持ち込むと害になるもの**もある。

- カタログの種別タブ・Product絞り込み・「さらに読み込む」は、リソース355件だから成立する。本アプリは**3カテゴリ・31単元**なのでフィルタUIは空振りする（§4-1 で不採用）。
- サインイン導線・進捗保存の訴求は、本アプリでは共有URL＋LocalStorageで既に解決済み。移植しない。

### 4-1. レベル1：カタログ

```

│ 英文法ミニレッスン        パンくず       保存状況      │
└──────────────────────────────────────────────┘
  今回の学習（主CTA 1つ・現行 .recommend を継承）
  4指標（完了単元／要復習／マスター／修了テストBEST）
  今日の復習 ← 期限到来 0 件なら非表示（現行ルール維持）
  ── 文法カテゴリ ──────────────────────────
  ┌ 仮定法 ────┐ ┌ 分詞 ─────┐ ┌ 不定詞 ────┐
  │ カテゴリ    │ │ カテゴリ    │ │ カテゴリ    │

  │ 完了 3/12   │ │ CLEAR ✓     │ │ 未着手       │
  └───────────┘ └───────────┘ └──────────┘
```

- **現行の折りたたみ式カテゴリナビゲータ（`courseNavigatorHtml()`）を廃止し、カタログを常設の第1画面にする。** 現行はカテゴリ比較が `<details>` の中に隠れており、Academy でいうカタログが存在しない状態にある。
- カードのメタ行は Academy と同じ語彙順（`種別 · 分量 · 所要時間`）に揃え、その下に本アプリ固有の進捗行を置く。既存 `courseCardModel()` の導出値をそのまま使い、新しい永続状態は持たない。
- **フィルタ・検索・ページングは置かない。**3カテゴリでは操作コストだけが増える。種別バッジは「カテゴリ／復習」の2値で足りる。

## 5. 必要なデータ追加

いずれも**既存フィールドを変更せず、任意フィールドの追加のみ**。未定義なら現行の見え方に落ちる（無回帰）。

### 5-1. 章（`course.sections`）

```js
sections: [
  { id: "basics", title: "現実と仮定の区別", lead: "…", lessonIds: ["conditionals-vs-subjunctive", "past-subjunctive", "past-perfect-subjunctive"] },
  …
]
```

- `lessonIds` は既存 `lesson.id` を参照するだけで、単元IDも表示順も変えない。
- 検証: `scripts` の教材チェックに「全 `lessonIds` が実在し、重複なく全単元を覆う」を追加。覆えていなければ章表示を無効化してフラット表示にフォールバックする。

### 5-2. 所要時間（導出・データ追加なし）

```
単元の目安分 = ceil(各論本文の文字数 / 500) + 問題数 × 1
カテゴリの目安分 = 全単元の合計（表示は 5 分単位で丸め）
```

- 手書きの `estMinutes` は**持たない**。教材を書き足すたびに実体とずれるため。上書きが必要な単元だけ任意の `estMinutes` で上書き可能にする。
- 係数（500字／分・1問1分）は `DESIGN.md` に定数として明記し、表示は必ず「約」を付ける。

### 5-3. 学習内容（`course.objectives`）

Academy のコース詳細で最も価値がある部分で、これだけは**導出できない**（既存の `takeaway` は問題単位で粒度が細かすぎ、31単元×3問＝93件になる）。カテゴリごとに 4〜8 項目を手書きする。合計 3 カテゴリ分＝最大24行なので、執筆コストは小さい。

## 6. ルーティング

現行は URL に状態を持たず、`state.coursePositions` からの復元のみ。3階層化すると「カタログへ戻る／カテゴリへ戻る」が頻出するため、ハッシュルーティングを入れる。

| ハッシュ | 画面 |
| --- | --- |
| `#/` | カタログ |
| `#/c/subjunctive` | カテゴリ詳細 |
| `#/c/subjunctive/l/past-subjunctive` | 各論 |
| `#/c/subjunctive/l/past-subjunctive/practice` | 練習 |
| `#/c/subjunctive/l/past-subjunctive/result` | 結果 |
| `#/c/subjunctive/final` | 修了テスト |
| `#/review` | 今日の復習 |

- **単元IDをURLに出す**（`state.stage` の数値インデックスは出さない）。単元の増減で既存リンクが別単元を指す事故を防ぐ。
- 読み込み時の優先順位: **ハッシュがあればハッシュを採用／なければ保存位置を復元**（現行動作を維持）。
- 生徒共有URLの `?s=` `&t=` はクエリなので併存する。`?s=…#/c/subjunctive` が成立することをテストで固定する。
- 内部状態は `state.stage` の数値インデックスのまま置く（§8 の保存互換のため）。ハッシュ↔stage の変換は読み書き時だけ行う。

## 8. 保存データの互換性（不変にするもの）

刷新は表示層に閉じる。以下は一切変更しない。

- 保存キー `englishGrammarLearning.v3` と全フィールド構造（`stage` は数値インデックスのまま）
- `stagesFor()` の段の並び（`overview` → 単元ごとに `lesson`/`practice` → `final`）
- 単元ID・問題ID・カテゴリID
- 間隔反復（`state.review`）の判定・Leitner 間隔・0時境界
- 修了テストの `state.finalChecks` と、問題数変動時の `cleared` 無効化
- クラウド同期（`app_students` / `app_progress`、正規化順序、`cloudStudent` スタンプ）

「ホーム＝`stage.type === "overview"`」という現行の判定（[app.js:560](../app.js)）だけが分岐点になる。ここへ `state.view`（`catalog` / `course` / `session`、**非永続**）を追加し、`overview` を「カテゴリ詳細」に読み替える。`state.view` を保存しないことで、既存の保存データは無変換で読める。

## 9. 判断点

### A. サイドバー再導入の是非 → **決定済み（2026-08-21・ユーザー承認）**

**サイドバーを持ってよい。**§4-3 の3ペイン構成をフェーズ3として実施対象に含める。

これに伴い、`DESIGN.md`「画面構成」の以下2文は**フェーズ3で置き換える必要がある**（§8 の「不変にするもの」には含まれない）。

> 内容レールは `min(920px, 100% - 32px)` を上限とする1カラム（`.wrap`）。**サイドバーは持たない。**

本リポジトリは過去にサイドバーを実装し（`1fe4cbf` / `260ee98`）、`c036866` で撤去している。同じ撤去に至らないよう、§4-3 の受入条件（本文行長 680px 上限の維持／練習・結果では非表示／900px 未満では折りたたみへ降格）をフェーズ3の完了条件として `DESIGN.md` に明記する。

### B. `course.objectives` を書くか
書かない場合、カテゴリ詳細は「判断のポイント＋章分けされた単元一覧」だけになる。Academy 構造の中核が1つ欠けるが、他は成立する。

### C.「役に立ちましたか？」の移植
本アプリには送信先がない。移植するなら**自己評価（理解できた／あやしい）→ あやしい単元の問題を翌日に前倒し**という形で間隔反復に接続する案があるが、これは §8 の「`state.review` の判定は不変」に触れる。**既定は移植しない**。

**フェーズ1と2だけでも Academy 構造の主要な価値（3階層の明確化・開始前の意思決定ページ・章による分量の分割）は得られる。**フェーズ3は §9-A で承認済みだが、フェーズ2までで一度リリースし、章データ（§5-1）が入った状態で左アウトラインを作るのが順序として安全（章がないとアウトラインは31項目のフラットな列になり、撤去時と同じ「情報量が多いだけのカラム」に戻る）。

**フェーズ3はフェーズ2に依存する。**先に3ペインだけ作らないこと。

## 11. やらないこと

- リソース種別のフィルタ・全文検索・「さらに読み込む」（3カテゴリでは無意味、§2）
- サインイン導線・アカウント訴求（共有URLで解決済み）
- 動画埋め込み・YouTube 導線（教材が文章＋4択のため）
- 配色・タイポグラフィの変更（本案は情報構造の刷新に限定する。トークンは `DESIGN.md` の現行値を使う）
- 教材本文の書き換え（章の追加は `lessonIds` の参照のみで、本文・単元IDに触れない）
