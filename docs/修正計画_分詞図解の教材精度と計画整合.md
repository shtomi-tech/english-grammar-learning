## 2. 評価結果と修正方針

### 2-1. 補語の矢印が説明方向と逆に読める

対象: `content.js` の `participle-complements`

現在の図解:

```text
主格補語: S → C
目的格補語: O → C
```

図解の中心概念は「補語Cが主語Sまたは目的語Oの状態を説明する」である。一方、既存図解では矢印がS／OからCへ向き、S／OがCを説明する、または処理がCへ進むようにも読める。ほかの図解で矢印を関係・結果の方向として使っているため、ここだけ語順を矢印で示すと意味が揺れる。

#### 採用する修正

```text
主格補語: S = C
目的格補語: O = C
```

補助文も次へそろえる。

```text
Cは主語の状態
Cは目的語の状態
```

- `=`は完全な同一性ではなく、補語がS／Oについて述べる叙述関係を示す教材上の簡略記号として使う。
- anchorの`S + V + C`／`S + V + O + C`は語順を示す一般式として維持する。
- bodyでは語順ではなく、補語がどの要素の状態を説明するかを示す。
- `The door remained locked.`、`We kept the engine running.`などの具体例と詳説は変更しない。

#### 採用しない案

- **`C → S`／`C → O`**: 説明方向は明確だが、英文の語順と逆向きになるため、初学者が別の語順規則と誤認しやすい。
- **矢印を残して補助文だけ変更する**: 大きな記号と小さな補助文が競合したままになる。
- **`SVC`／`SVOC`だけにする**: 補語が何を説明するかという単元の中心判断が弱くなる。

### 2-2. 知覚動詞の一般式が`see / hear`だけに見える

対象: `content.js` の `perception-verb-participles`

現在のanchor:

```text
see / hear + O + -ing / p.p. / 原形
```

後半では`see / hear / watch / feel / notice`を知覚動詞として扱っている。大きなanchorは具体例ではなく一般式として読まれるため、`see / hear`だけを置くと、ほかの知覚動詞では同じ形を使えないように見える。

#### 採用する修正

```text
知覚動詞 + O + -ing / p.p. / 原形
```

- 一般式はカテゴリ名で示す。
- `see / hear / watch / feel / notice`は後半の既存詳説で具体例として残す。
- bodyの`-ing`／過去分詞／原形不定詞の3分岐は変更しない。
- leadとpromptの「目的語と動作の関係」「途中／受動／一連の動作」を維持する。
- 新しい知覚動詞、問題、用法は追加しない。

#### 採用しない案

- **5動詞をすべてanchorへ列挙する**: 一般式が長くなり、320pxで具体例の一覧が主役になる。
- **`see / hear`の後ろへ`など`だけを加える**: 代表例であることは示せるが、一般式と具体例の役割分担が曖昧なまま残る。

### 2-3. Gateの内部確認とユーザー承認が混同されている

対象: `docs/実装計画_分詞概論と各論の図解教材化.md`

当初計画のGate A・Gate Bは、試作をユーザーが確認し、承認後に残り単元へ展開する境界だった。現在の実装結果では、focused E2Eと実ブラウザによる内部検証を「Gate確認」として記録し、同じ実装作業内で全5単元へ展開している。

内部検証自体は有効だが、ユーザー承認の代替ではない。承認者、承認日、承認内容を後から補完せず、実際に確認できる事実だけを記録する。

#### 採用する修正

- Gate A・Gate Bは「当初計画したユーザー承認点」として残す。
- 現在の「Gate確認記録」は「段階別の内部検証記録」へ改称する。
- 「その後、残りの単元へ展開した」という実装順は事実として残す。
- 「ユーザー承認前に全5単元へ展開済みである」と明記する。
- 本修正後の再確認を、当初Gateの遡及的な承認として扱わない。
- ユーザーが明示的に承認した場合だけ、承認日と対象を別行で追記する。

### 2-4. テスト追加件数と合計件数が混同されている

対象: 同実装計画の「15-1. 変更内容」

現在の記録:

```text
tests/participles.spec.mjsへ…13件を追加した。
```

実際には既存8件へ5件を追加し、合計13件になっている。

#### 採用する修正

```text
tests/participles.spec.mjsへ図解関連の5件を追加し、合計13件とした。
```

検証結果の「13件成功」は合計件数として正しいため維持する。
