## 1. 目的

不定詞14単元の各論を、概論で採用した次の二段構成へ変更する。

1. **上部で見る**: 大きなHTML図解と少ない言葉で、その単元の中心概念をつかむ。
2. **後半で読む**: 現在の詳しい説明・例文・対比・注意点を常時表示する。

図解は装飾ではなく、学習者が例文を読む際に使える判断手順を示す。単元ごとに中心概念は異なるため、全単元へ同じ3カードを複製せず、「役割」「関係」「対比」「語順」「時間軸」に合う図解型を使い分ける。

## 2. 現状確認

### 2-1. 教材と進捗の契約

| 項目 | 現状 | 本計画での扱い |
| --- | --- | --- |
| 不定詞 | 14単元・42問 | 単元数・問題数を変更しない |
| 単元ID・問題ID | 公開済みの安定ID | 変更しない |
| `lesson.version` | 単元ごとに1〜3 | **図解追加だけでは上げない** |
| `structureVersion` | `infinitives: 1` | 変更しない |
| 保存キー | `englishGrammarLearning.v3` | 変更しない |
| 回答・復習・修了テスト | `answers` / `review` / `finalChecks` | 内容・判定・保存形式を変更しない |

`syncContentVersions()` は版が変わった単元の回答、既読状態、復習記録を削除する。そのため、説明を視覚化するだけの本変更では `lesson.version` を更新しない。実装中に問題や学習上の正解を変える必要が判明した場合は、本計画へ混ぜず、別の教材修正として影響を確認する。

### 2-2. 描画経路

各論は次の順で描画されている。

```text
content.js の lesson.html
  ↓ renderLesson()
.flashCard 内へ挿入
  ↓ renderExplanationSections()
details.section を常時表示の section.section へ変換
  ↓ buildLessonToc()
.section > .sectionHeading だけからページ内目次を生成
```

このため、図解を `lesson.html` の先頭へ追加するだけなら `app.js` の変更は不要である。図解内の見出しに `.sectionHeading` を付けなければ、既存のページ内目次数も変わらない。

### 2-3. 現在の説明量

- 各単元の説明節: 3〜6節
- 1280pxでの各論カード高: 1,180〜2,382px
- 320pxでの各論カード高: 1,894〜3,561px
- 現状の全14単元で横スクロールなし、コンソール・ページエラーなし
- 現在は単元タイトルのあと約180〜249pxで最初の詳説節が始まる

図解を追加すると各論全体はさらに長くなる。後半を削除して帳尻を合わせず、図解自体をデスクトップで概ね420〜560px、320pxで概ね480〜650pxに収める。複雑な図解でも320×800の1画面を大きく超える720px以上にはしない。

## 4. 共通コンポーネント設計

### 4-1. 配置

各単元の既存導入段落より前、`<h3>${lesson.title}</h3>`の直後に図解を置く。

```html
<section class="lessonVisual lessonVisual--roles" aria-labelledby="infinitive-nominal-visual-title">
  <div class="lessonVisualAnchor">...</div>
  <p id="infinitive-nominal-visual-title" class="lessonVisualLead">...</p>
  <div class="lessonVisualBody">...</div>
  <p class="lessonVisualPrompt">...</p>
</section>
<p>既存の詳しい導入説明...</p>
<details class="section" open>...</details>
```

### 4-2. 必須スロット

| スロット | 役割 | 制約 |
| --- | --- | --- |
| `.lessonVisualAnchor` | 一般式、文型、時間軸など | 具体例を一般式の代わりにしない |
| `.lessonVisualLead` | 単元の中心概念を一文で示す | 専門用語を知らなくても読める短文 |
| `.lessonVisualBody` | 2〜4個の並列情報または関係図 | 同じ分類軸でそろえる |
| `.lessonVisualPrompt` | 例文を読むときの判断基準 | すべての枝に使える問いにする |

図解はHTMLとCSSで構成する。画像生成、SVGライブラリ、Canvas、GSAP、新しい外部依存は追加しない。

### 4-3. 図解型

| 型 | クラス例 | 用途 |
| --- | --- | --- |
| 役割・スロット | `--roles` | 主語・目的語・補語など、文中の位置を示す |
| 関係・流れ | `--flow` | 動作→目的、感情←理由、出来事→結果など |
| 対比 | `--contrast` | 目的/結果、for/of、原形/-ingなど |
| 文型・語順 | `--sentence` | It構文、使役・知覚、notの位置など |
| 時間軸・程度 | `--timeline` / `--scale` | 完了不定詞、too/enoughなど |

型は見た目の違いではなく、学習者が判断するときに使う関係の違いを表す。1単元につき主となる型は1つに絞る。

### 4-4. 視覚規則

- 概論と同じ12px角丸、3pxの主要罫線、影なしを使う。
- 既存の`--color-learning-*`と役割トークンを再利用し、単元ごとに色を直接指定しない。
- 色だけで分類せず、ラベル・配置・矢印・枠線を併用する。
- 大きな一般式、中心文、カード本文を同じ強さにしない。最重要は1つだけにする。
- 図解内の本文は16pxを基本とする。補助語でも12px未満にしない。
- 固定の高さ、`white-space: nowrap`、`word-break: break-all`を使わない。
- 数字は本当に順序がある場合だけ使う。分類には番号を付けない。

### 4-5. レスポンシブ

| 幅 | レイアウト |
| --- | --- |
| 641px以上 | 2〜3列、または横向きの関係・時間軸 |
| 321〜640px | カードは短い横長行、対比は縦積み、矢印は上下方向へ変更可能 |
| 320px | 1列。左右余白を確保し、英文と文型を自然に折り返す |

受入条件:

- 320 / 375 / 640 / 1280pxでページ横スクロールなし。
- 320pxで単純型は650px以下、複雑型も720px未満。
- 320pxの並列カードは、内容差による高さの振れ幅を原則36px以内にする。
- 図解の次に既存導入段落が続くことが視覚的に分かる余白を置く。

## 5. 単元別の図解設計

| # | 単元ID / 単元名 | 図解型 | 上部で伝える内容 | 最後の判断基準 |
| ---: | --- | --- | --- | --- |
| 1 | `infinitive-nominal-use` 不定詞の名詞的用法 | 役割・スロット | `to do`を1つの「文の部品」として、主語・目的語・補語の3位置へ置く | `to do`を「～すること」に置き換え、文のどの部品かを見る |
| 2 | `infinitive-adjective-use` 不定詞の形容詞的用法 | 関係 | `名詞 ← to do`とし、名詞を後ろから説明する関係を示す。対象の場合と前置詞が残る場合を小さく補助 | 不定詞の直前に、説明される名詞があるかを見る |
| 3 | `infinitive-adverbial-purpose` 副詞的用法（目的） | 流れ | `主節の動作 → 何のために？ → to do`。`in order to`と`so as to`は同じ目的の強調として補助 | `何のためにその動作をしたか`で自然かを見る |
| 4 | `infinitive-adverbial-reason` 副詞的用法（原因・理由） | 逆向きの関係 | `to do → 感情・判断`として、目的とは矢印の向きが異なることを示す | 不定詞が、感情・判断が生じた理由かを見る |
| 5 | `infinitive-adverbial-result` 副詞的用法（結果） | 時系列・対比 | `主節の出来事 → 実際の結果`。目的は意図、結果は実際に起きたこととして並べる | `何のために`ではなく`その後どうなったか`で読めるかを見る |
| 6 | `infinitive-adverbial-degree` 副詞的用法（程度・結果） | 程度スケール | `too`は可能ラインを越えて不可能、`enough`は必要ラインに届いて可能、と1本の尺度で対比 | 形容詞の程度から、可能・不可能という結果が出ているかを見る |
| 7 | `infinitive-logical-subject-for` 不定詞の意味上の主語 | 担当者の関係 | `for + 人`から`to do`へ「この動作をする人」の線を引く。目的格も同じ位置で示す | `to do`を実際にするのは誰かを見る |
| 8 | `infinitive-of-adjective-evaluation` 人の性質を表す形容詞と不定詞 | 対比 | `for = 動作主`、`of = 人の性質・行動を評価`を同じ文型上で対比 | 形容詞がその人自身を評価しているかを見る |
| 9 | `dummy-subject-it` 形式主語構文 | 文の並べ替え | 長い`to do / that節`を後ろへ移し、先頭の空席を`it`が埋める図 | `it`が具体物を指さず、後ろに本当の内容があるかを見る |
| 10 | `dummy-object-it` 形式目的語構文 | 文型・語順 | `S + V + it + C + to do`を5スロットで示し、`it`と後ろの内容を線で結ぶ | `it`の後ろに補語があり、さらに後ろに判断内容があるかを見る |
| 11 | `bare-infinitive` 使役動詞と原形不定詞 | 文型・対比 | `make / let / have + 人 + do`。強制・許可・依頼を並列化し、受動の`be made to do`だけtoが戻る | 前の動詞、動作主、能動/受動の3点を見る |
| 12 | `perception-bare-infinitive` 知覚動詞と原形不定詞 | 対比 | `see + 人 + do = 動作全体`、`see + 人 + doing = 途中`を同じ場面の時間幅で対比 | 知覚したのが動作全体か、途中の場面かを見る |
| 13 | `infinitive-negative-form` 不定詞の否定形 | 語順 | `not → to → do`を大きく示し、`decide not to buy`と`do not decide to buy`で否定範囲を対比 | `not`が主節と不定詞のどちらを否定しているかを見る |
| 14 | `infinitive-perfect-form` 完了不定詞 | 時間軸 | 左に`to have done`、右に主節の基準時を置き、完了不定詞が必ず前であることを示す。受動は`to have been done`として補助 | 主節の時点と比べ、不定詞の出来事が先かを見る |

### 後半へ必ず残す内容

図解は入口であり、次の情報を置き換えない。

- 各用法の完全な定義
- 現在の例文と日本語訳
- 似た用法との比較
- `only to`、`in order to`、`so as to`などの定型表現
- `for + 人`と`of + 人`の詳細な判断
- that節を使う発展内容
- make / let / haveの意味差と受動態
- 否定形・完了形の受動態
- 各単元末尾の見分け方

初回実装では既存の説明文を削除・要約しない。図解との重複が過剰かどうかは、全体表示を確認した後の別判断とする。
