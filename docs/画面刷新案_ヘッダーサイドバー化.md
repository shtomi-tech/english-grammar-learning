## 1. 動機とスコープ

現行は1画面1段階・`min(100% - 32px, 720px)` の単一カラムで、構成リスト（単元一覧）はページ下部に折りたたみ表示。ユーザー要望は次の2点：

2. **Windows（広い画面）ではもっと画面を広く使う。**

この提案は **DESIGN.md の「画面構成」「視覚ルール」の2セクションのみを置き換える対象**とする。以下は変更しない（実装ロジック・保存形式に触れない）。

- 修了テストの解放条件・出題・`state.finalChecks`
- 今日の復習（間隔反復）の対象判定・Leitner間隔・0件時の非表示ルール
- 保存キー `englishGrammarLearning.v3` と各フィールドの構造
- 生徒別進捗のクラウド同期（`?s=`＋token、正規化順序、`cloudStudent` スタンプ）
- 教材データの構造（`curriculum.courses`、単元ID・カテゴリIDの不変性）

## 3. 画面構成（新）

### 3-1. レイアウト

```
┌─ header (topbar) ───────────────────────────────────────────┐
│ ブランド              現在地パンくず           保存状況        │
└───────────────────────────────────────────────────────────┘
┌─ sidebar (sticky) ─┬─ workspace ──────────────────────────┐
│ 今日の復習カード     │  本文（概論／各論／練習問題／結果）        │
│ コース切替タブ       │  実測幅は680px程度に固定                │
│ 構成リスト           │  （シェル自体は広いが、行長は現行同等に保つ）│
│ 修了テスト           │                                       │
└─────────────────────┴───────────────────────────────────┘
```

- シェル最大幅 `1240px`、`grid-template-columns: 268px minmax(0,1fr)`、`gap: 28px`。
- サイドバーは `position: sticky` で常時表示（デスクトップ幅）。
- 本文・選択肢は `workspace` 内で `max-width: 680px` に固定し、読みやすさは現行を維持。**広い画面で使うのは「サイドバーの常時可視性」と「余白」であり、行長ではない。**

### 3-2. ヘッダー

- 現行の「要約表示に絞り、縦に伸びる要素を置かない」ルールは維持。
- 構成: ブランド（アプリ名）＋現在地パンくず（`仮定法 ＞ 仮定法過去 ＞ 練習問題（2/3）`）＋保存状況。
- 「続きから」CTAのような新機能は**今回のスコープ外**（構造・視覚の刷新のみに限定し、機能追加は混ぜない）。

### 3-3. サイドバー（新規要素・要確認）

現行はページ下部の `<details>` 1本（既定閉）だったものを、常時表示のサイドバーへ移す。これに伴い、以下は**新しい決定**であり、実装前にユーザー確認を推奨する。

1. **今日の復習バナーの位置**：サイドバー最上部に固定表示へ変更。
   現行ルール（本文直後・ページ下部＝「本文を読み終えた後の導線」）からの転換で、常時可視になる分目立つ。0件時は非表示・復習セッション中は非表示、というルールはそのまま踏襲。
2. **構成リストの粒度**：単元ごとに折りたたみグループ（見出しに正解数要約、内部に「各論／練習問題」の2行）とする。
   仮定法だけで9単元×2段＝18行あり、フラットなリストのままサイドバーに置くと縦に伸びすぎるため。現在の単元は展開、他は見出しのみの折りたたみ（現行の「現在の単元／全単元数」の考え方を単元単位に適用）。
3. **コース切替**：`仮定法` / `分詞` をタブ状のボタンで切替。将来単元カテゴリが増えてもタブが横に並ぶだけで縦の圧迫にはならない。

### 3-4. レスポンシブ

| 幅 | 挙動 |
|---|---|
| 〜1240px（デスクトップ） | サイドバー常時表示・sticky |
| 〜1000px | サイドバーは `position: static`（本文の上に積む）に変更（`english-level-check` と同じ閾値） |
| 〜640px（スマホ） | ヘッダーは縦積み。サイドバーは「学習の構成・今日の復習を見る」の1本のトグルに収納し、閉じた状態でも復習件数をチップで表示（0件なら現行同様チップごと非表示）。決定系ボタンは縦積みでも先頭に来る現行ルールを維持 |

モックアップは1240px幅と375px幅の2フレームのみ提示。1000px帯の中間状態は上表の方針どおり実装時に作る。

## 5. 実装時の簡略化（モックアップとの差分）

- モックアップのスマホ幅フレームは「学習の構成・今日の復習を見る」という1本のトグルに両方を収納し、復習件数をチップで表示する案だった。実装では、今日の復習バナー（`#review-banner`）とコース切替（`#course-selector`）は`<details class="progress-details">`の**外**に置き、常時表示のまま据え置いた。折りたたみトグルの対象は構成リスト（`#steps`）だけ。理由：元々`#review-banner`は0件時のみ非表示・復習セッション中は非表示という独立した表示ロジックを持っており、そのままサイドバー上部に置けば「常時表示で復習件数が見える」というモックアップの狙いをチップなしでも満たせるため、新規UI要素（チップ）を追加しなかった。
- 単元一覧の折りたたみ開閉は端末に保存せず、現在地（`state.stage`）から毎回導出する方式にした（旧`state.branchOpen`は廃止）。単元数が増えるほどグループ数は増えるが、開閉状態を1つの真実の源（現在地）から出す方が単元ごとの永続化より単純なため。
- 修了テスト行のバッジ文言は、既存の`finalStatusFor()`（未解放／挑戦可能／CLEAR判定）をそのまま再利用した。ロック理由の詳細（あと何単元か）は本文側（修了テスト画面）に表示され、サイドバーには要約ラベルのみを出す。
